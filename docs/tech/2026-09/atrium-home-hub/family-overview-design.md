# 家庭今日概览：数据与展示契约

2026-09-12 · M3-A 架构草案。M2 照片体验开发期间提前梳理；本文不是已经接入日历、房屋或简报的证明。真实日历来源与公开字段已向用户询问，未获答复前不连接私人账户或读取个人日历。

## 目标与来源

家庭今日概览由确定性代码汇总日程、家庭提示、房屋资料与中枢状态；模型不可用时仍正常展示。延续 Go Core、SQLite、React TV、既有屏幕鉴权。AI 的已有十个模型工具保持当前范围，不自动把新日历或房屋内容发送给模型。

| 模块 | 可用基础 | 尚待明确 |
| --- | --- | --- |
| 房屋 | 已授权 Core / NAS / 当前屏幕的真实观测 | 用户愿意公开的房间名、说明；传感器来源 |
| 家庭提示 | `widgets.notice` 的维护者静态提示 | 更新时刻、有效区间、多个提示的维护方式 |
| 日历 | 现有家庭 IANA 时区 | 一个明确授权的共享来源、允许公开的字段 |
| 简报 | 前述模块的公开投影 | 有真实来源后再验收完整今日概览 |

中枢在线、共享目录可读与房屋环境正常是不同事实。未连接温湿度或门窗传感器时不产生数值、正常结论或虚构房间。家庭位置不能由时区推断。

## 共同数据语义

模块包络以 `schema_version`、`source_id`、`source_label`、`observed_at`、`updated_at`、`expires_at`、`availability`、`items` 表达。时间均带明确偏移；未知时间为 null，不能使用响应生成时间冒充内容更新时间。

`availability` 使用 `not_connected | loading | available | stale | failed`。只有一次完整、成功且有效的读取返回 `available` + 空列表时，才能显示“没有公开事项”；未接入、过期或失败不能转换为空成功。响应生成时间另设 `generated_at`。短时故障可以保留仍允许公开的旧投影，但显式标为 stale，并显示最近成功读取时间；权限撤销立即清除内容。

数据可用性与被观测对象的健康是两个字段。例如已成功读取到 NAS 降级状态，模块可以是 `available`，其中来源的 `health` 为 `degraded`；不能因为 NAS 不健康就把这条真实观测丢失，也不能把模块读取成功写成“房屋正常”。当前 Core 的 NAS 投影可提供来源 ID、显示名称、最近检查/成功时刻与可空空间值；现有 admin-only 的卡住 I/O 详情、挂载身份与路径继续只留在维护端。

页面文案按以下状态表落地，避免各页自行解释：

| 模块状态 | 内容处理 | 日历示例 |
| --- | --- | --- |
| not_connected | 不含事件，不计算“零条” | 尚未连接家庭日历 |
| loading | 首次读取中，不作空成功结论 | 正在读取公开日程 |
| available，空 | 本次成功读取覆盖旧列表 | 当前范围没有公开日程 |
| available，非空 | 展示公开投影和来源 | 展示议程 |
| stale | 保留仍获授权的旧投影并标最近成功时间 | 日历暂未更新，显示上次日程 |
| failed，无旧投影 | 不展示旧/示例事件 | 暂时无法读取日历 |
| 授权撤销 | 清空投影、缓存和待展示状态 | 该日历已停止共享 |

撤销不是第六种可用性状态：清空后返回 `not_connected`，另以稳定原因码 `sharing_stopped` 区分从未连接；不能变成可长期保留内容的 stale。异步读取需携带来源配置代次；旧代次结果不能在来源删除或重新授权后恢复旧内容。TV 屏幕本身的撤销和现有 24 小时授权时限同样覆盖这些新模块。

所有面向 TV 的对象只包含经过公开字段筛选的内容。原始订阅 URL、凭据、NAS 路径、账户邮箱、参会者、备注、附件、会议链接和未经允许的地点不进入 TV API、日志或模型工具。数据更新不抢夺遥控焦点，也不跳出正在浏览的照片或视频。

## 日历适配边界

先提供统一的只读适配接口，再按用户选择实现一个来源。若选择 ICS，使用受限读取和完整解析库；不要用按行拆字符串代替日历解析。网络订阅地址只来自维护者配置，禁止 TV 或 AI 参数改变目标地址；密钥不放 URL 日志或仓库。设置单次大小、事件数量、重复展开窗口和超时上限，后台同步，首页请求不等待外网。

时间模型区分全天日期与带时区的时间点。全天事项保留日期边界，结束日期按非包含边界处理；重复事件按限定议程窗口展开并处理例外。浮动时间使用明确配置的家庭时区，并保留该解释信息。跨日事件按家庭日界投影，不以设备时区截断。这些基础语义依照 [iCalendar RFC 5545](https://www.rfc-editor.org/rfc/rfc5545) 的 DATE / DATE-TIME、VEVENT、RRULE、EXDATE 与 RECURRENCE-ID 定义；实现前按所选库的支持范围补兼容清单。

公开事件字段建议为稳定公开 ID、标题或“家庭日程”占位、开始/结束、全天标记、来源标签和数据状态。标题是否可见由用户公开字段选择决定；不会把“已连接共享来源”自动解释为允许展示所有内容。取消与例外更新要能撤下旧投影；来源成功为空也须清空旧事项，防止旧日程长期残留。

## 房屋与提示

房屋页分开显示“房屋资料”和“中枢与来源状态”。房间资料只使用用户提供的公开文本；缺失时显示尚未填写。第一版无需新增传感器运行时，不提供设备控制。

现有 `internal/widget/composer.go` 每次 Compose 都把静态 notice 的 `UpdatedAt` 设为当前时间。M3 不能沿用它作为真实内容更新时间。静态提示需显式可空更新时间，并把配置装载/观测时间与内容修改时间分开；到期提示不进入今日简报。已有单条提示兼容保留，不凭文件 mtime 推断语义上的发布时间。

## 简报排序与页面

建议优先级：明确异常或同步失败 → 当前及近期公开日程 → 有效家庭提示 → 简洁来源摘要。每条记录携带来源和有效性；没有事项时保持留白并给真实来源状态。单个模块失败不让整个首页失败，不使用“家里一切正常”兜底。

页面继续宋式字体、留白、焦点和返回规则。M3 完成真实联调前不在生产导航开放演示数据入口；无日历来源时真实状态页可以显示“尚未连接”。日历与简报先做议程列表，无需首期实现密集月历。

## 落点与实施门槛

- 新增 `internal/calendar` 适配/缓存与日期投影，`internal/briefing` 确定性汇总；先在独立类型和单元测试中定义上述包络。
- 扩展 config 校验与脱敏，再新增独立 screen API（建议 `/api/v1/family/overview`、`/api/v1/family/calendar`、`/api/v1/family/house`）。具体路径在实现前随 OpenAPI 定稿，不把建议路径记为可调用。
- 首页只读取廉价缓存投影；不增加同步 NAS/网络 I/O。家庭日历更新可复用 home 变更通知与节流，再按实际需求决定是否新增 topic。
- 持久化只保存必要公开投影与同步状态。来源连接完成前不动生产迁移；连接后先确定缓存销毁与撤销语义，再创建迁移和升级测试。
- 测试覆盖家庭日界、全天/跨日/重复及例外、成功空数据、断网旧缓存、撤销清除、单模块失败隔离、内容更新时间真实性、默认私密字段排除。

M3 出口仍要求一个真实授权日历来源和真实家庭提示/公开资料场景。仅文档、模拟日历或未连接页面不能算完整家庭概览交付。Mac 断电恢复、NAS 自动挂载继续暂停。
