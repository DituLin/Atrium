# 按需照片预览与小容量缓存

中文 | [English](photo-cache.en.md)

更新：2026-11-04。状态：已实现并通过代码验证，部署结果尚待本次发布验收。

## 存储方式

NAS 保留照片原片。Mac 保存索引、元数据，以及播放和浏览时生成的 JPEG 预览图与缩略图。按需模式不为整份新图库提前生成预览；元数据就绪后，照片可以成为播放候选，首次访问时再通过正常解码管线生成衍生图。

首页从可展示且来源仍获授权的索引中计算每日顺序，缓存文件被淘汰不会使照片退出随机池。已确认不支持、生成永久失败、被排除、被移除或来源被撤销的照片仍被过滤。多个来源按照片混合，不按来源平分配额。

首页只为当前照片和后续最多三张准备预览，不因取得一页元数据而生成整页图片。影像网格按可见区域准备缩略图。续播位置仍在照片成功显示后保存；仅仅预加载不会推进进度。NAS 离线时，已有缓存可以继续使用，缺少预览的照片暂时跳过。

## 配置

以下片段需要合入现有配置，不要覆盖来源、档案或授权设置：

```yaml
storage:
  cache_budget_bytes: 2147483648 # 2 GiB，约 2.15 GB
media:
  preview_mode: on_demand
```

`preview_mode` 可选 `eager` 或 `on_demand`。默认 `eager` 保留原来的元数据后批量生成方式；`on_demand` 在播放或浏览请求时生成预览。这里只改变衍生图片的准备时机，不复制整份 NAS 原图库。

额度覆盖照片预览、缩略图和启用时的视频封面；数据库、档案原件、日志、备份、发布包和临时文件另计。清理按较久未访问优先执行，超过照片分区额度时回收至约 90%；服务启动后也会检查缩小后的额度。并发写入和临时转换可能短暂增加磁盘占用，额度不是整个应用的硬磁盘上限。

## 维护与验证

受控修改配置并重启 Core 后，确认来源身份与原有配对不变、索引数量保留、后台清理释放超额衍生文件。无需重置图库索引或重新授权来源。缩略图清理不应把仍有大图预览的照片错误标为整图不可用；实际大图被清理后仍能按需再生。

首次生成可能比命中缓存慢，尤其是 HEIC 转码或 NAS 响应较慢时。验证应覆盖空缓存首屏、下一张准备、清理后的随机顺序与续播、来源撤销、缓存占用及实际 TV 播放。原片目录继续保持只读。
