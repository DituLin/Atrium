# 整行生长曲线实施计划

**目标：** 按提供截图，在奶量/构成卡下一排新增横跨三列的生长曲线，原身高、体重与财务小卡顺延。

**架构：** 复用已验证人物 GrowthData 和相同 generation 生命周期；独立纯数据汇总、SVG 曲线与 UI 卡片。数据仍按单位与样本分组，默认身高，可遥控切换体重。左侧最新实测、测量日与观察到的增长，右侧日期横轴、数值纵轴、实测点与平滑连线。不存在的测量不补点、不补零。

**数据边界：** 公开人物接口只有名称，没有出生日期或性别，不能按名字或截图示例推断。WHO 参考仅能在资料和权威标准表均已核实时显示；缺少时显示实测曲线、实际日期和明确缺项提示，不展示虚构百分位或“正常”诊断。用户已异步询问所需资料，独立布局和真实数据工作继续。

**步骤：**

1. 为纯数据汇总写失败测试，复用 summarizeGrowth 的单位/样本/安全小数与时间顺序；近三月以最新实测为界，仅描述窗口内实际两次记录变化并保留真实起止日。
2. 为曲线与空态/切换/遥控写失败测试，实现新 GrowthCurve/Plot/CSS；跟随深色卡片和绿色渐变，不改变其它页。
3. 在 ArchiveDashboard 网格 milk+composition 后插入 span3 卡；把 milk下方向到新卡，新卡下方向到三小卡，详情/返回/人物切换与撤权保持已验证生命周期。
4. 核对 WHO 官方资料和现有资料接口，决定可用参考边界，不将待补项包装为已有能力。
5. 前端全量测试、lint/typecheck/build与Chrome66 API 检查，浏览器合成数据和 OnePlus 实机视觉/遥控验证；新增公共说明中英文同步。
6. 提交并按已有直接部署授权更新现役窄叠加包，保持 c06+LivePhoto+overview 后端源码；既有签名身份、隔离预检、一致性备份、原子切换与健康/数据/NAS校验。

公开样例仅合成资料；真实生日、性别、档案及截图不进入仓库。


## 资料确认后的范围

用户已确认人物的完整出生日期、性别和卧位身长。仅在本机私密配置保存这些输入，新增可选 `archives.growth_profiles` 并在完整、匹配的公开汇总快照中投影；`Redacted()` 不输出资料。WHO 每日 LMS 参数由官方男女童表提取为离线数值资料，记录来源与摘要，按测量日天龄计算参考线。卧位/站立与731天边界明确处理；超年龄、单位、缺项或不完整证据不计算比较。参考百分位和P3–P97区间仅描述数值位置，不作诊断。无实测时只绘参考线并明确暂无实测。
