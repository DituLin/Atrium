# 档案看板设计稿对齐实施计划

**目标：** 按已提供的 HTML 和截图实现三列档案看板、侧栏和最近档案卡，连接真实统计并保留档案权限、失效隐藏、投屏结果与遥控操作。

**架构：** 新增只读公开档案 overview，用同一授权/epoch/generation 快照统计全家文档、领域、实体和归属数量；客户端 reader 将其纳入当前已验证快照。奶量、成长和财务继续使用有界分析接口，精确或明确舍入后派生汇总。展示以 ArchiveDashboard 与独立 SVG 图表组成，详情和投屏查询保留既有路径。

**技术：** Go/SQLite、React/TypeScript、CSS Grid/SVG；Chrome 66 基线。

## 统计口径

- 档案构成固定为全家当前公开、未撤回档案，不随分页和当前人物变动；已确认/待确认按文档状态和归属判定，不使用事实排除计数冒充份数。领域/实体/归属数字按文档去重；上限或未追平时显式标记不完整。
- 奶量日视图显示同类、同单位和同样本的当天合计及记录条数；周/月显示有记录日均与记录天数，缺日不当零。保留最新记录时间/数值；不同种类不盲目相加。
- 成长按人物、单位和样本展示真实最新测量及与上次差值，无数据保留紧凑空态卡。
- 财务使用最近六个自然月的已确认金额，按币种/单位/样本分列。现有数据无统一收支方向，卡片名使用“财务金额”；当前月缺数据时不显示假零。差值和百分比仅在基线有效时显示。
- 统计和档案页必须使用同一 generation；失败、撤权和超时按既有规则隐藏，不以分页记录代替全量统计。

## 分工与步骤

1. Go overview（独立任务）：先为公开/私密/撤回/legacy、文档待确认、实体去重、屏幕撤销与边界写失败测试，再实现只读 store 和 HTTP 接线；不迁移 schema。
2. 前端统计（独立任务）：为今日 Core 合计、缺日/缺月、分组、小数、溢出、abort 与 generation 变化写红测，再实现 feedingTrend、financeTrend、dashboardStats。
3. 看板展示（独立任务）：三列网格，奶量跨两列、右侧构成，下排身高/体重/财务；卡内周期、右侧 Y 轴、渐变和末点、日期与增量徽标；匹配侧栏数量/选中态和最近卡的图标/正文/右侧日期。
4. Root 接线：API 类型/方法、reader 快照、页面组合/遥控焦点、状态和范围标识、mock server。保留投屏查询、详情、证据、预览、分页与30秒失效规则。
5. 验证：独立需求和质量审查；前端全测试、lint、typecheck/build、Chrome66 guard；Go相关测试及必要race；1920×1080和OnePlus viewport的合成数据截图逐项对照。
6. 提交与部署：主分支仅快进已验收分支；在现役 c06 后端 + Live Photo补丁基线上仅叠加本次后端文件和新前端，不携带其它主分支后端变化。既有身份签名，隔离升级预检，一致性私有备份，原子切换并验证数据、健康和OnePlus遥控。

所有公开测试/截图使用合成数据，真实家庭资料与凭据只留在私有本机目录。新增对外说明同步中英文。此修复不扩大 T15–T18 的验收结论。

## 实施验证

- 新增 overview、统计汇总、三列看板与合成 mock 已实现；独立审查发现的并发撤权保留旧快照、范围标签和属性读取预算问题均已修复并补回归。
- 前端 77 文件、541 测试通过；lint、typecheck、生产构建与 Chrome 66 API 检查通过。
- Go 全量串行测试及 overview store/HTTP race 检查通过。
- 1920×1080、804×384 合成页面验证五卡顺序、真实合计与差值、领域/人物筛选、日周月、遥控滚动、详情返回和空态；6 张私有截图，页面错误为0。
- 发布仅叠加到现役 c06 + Live Photo 基线；部署和正式应用结果待运行后记入双语发布证据。
