# Current family archive analysis

T12 adds `home_analyze_archives` to the actual MCP inventory, Brain executor and typed receipt pipeline, OpenClaw plugin manifest and receipt renderer. The model selects business criteria; Core performs arithmetic. The HTTP API supplies the configured household timezone and authenticated projection. Model arguments cannot supply timezone, projection, household, credentials, or pagination cursors.

Operations: `count` (explicitly documents, canonical events or observations), `sum`, `latest`, `series`, `ratio`. A metric is an observed field name; search evidence now exposes `field_name` to make it discoverable. Sources with current unresolved fields are not promoted to confirmed facts. Every response states `archived_only`, exclusions and coverage; an unknown household-wide denominator never becomes a completeness percentage.

## Numeric and temporal rules

- Decimal inputs are bounded strings: 72 integer and 18 fractional digits. Computation uses `math/big.Rat`; legacy JSON numbers are decoded with `json.Number`, never old `FamilyMeasurement.Value` floats or SQL REAL sums. Unsupported scientific notation and comparator values are excluded explicitly. Algorithm version 2 also checks an immediately adjacent, bounded (24-rune) original-source qualifier before accepting a normalized numeric span. Current explicit value assertions replace source value semantics; qualified assertions remain non-exact. The same rule applies to ratio denominators.
- Compatible field/currency/unit/sample groups remain separate; no implicit currency or unit conversion. Missing dimensions keep individual sums separate and mark incomplete coverage. Health/education sample groups preserve current owners. Sample/project, date, denominator and physically bound unit/currency fields use current assertions and retain their evidence. Hidden grouping dependencies exclude dependent public numeric results. Sums preserve maximum input scale. Ratios retain numerator, denominator, rounding (`half_away_from_zero/2`) and both source evidence sets. A uniquely ordered earlier compatible ratio supplies an exact percentage-point change; overlapping dates cannot select a baseline.
- Dates retain year/month/day/datetime precision. IANA household timezone defines day boundaries. Range overlap at insufficient precision is excluded with coverage. Latest returns all unresolved overlapping candidates; it does not turn a month into a chosen day. Event date fields are explicitly named; dates of birth and warranty expiry are not silently used as occurrence dates.
- Canonical observation IDs deduplicate multiple proofs. A labeled payment proof cannot suppress the corresponding labeled charge just because its document sorts first. Different values/revisions/dimensions in a canonical slot fail closed.
- Finance sum requires literal source role evidence (`line_item`, `total`, `payment`). The role parser recognizes explicit Chinese/English expense, total and payment labels immediately preceding a numeric span, in a preceding cell on the same table row, or a first-row column header. A model name or confidence is insufficient. Payment proofs do not add charges. A total is excluded only with an explicit aggregation membership proof: the current table rule recognizes a literal total after contiguous labelled line-item rows in the same physical table and value column, with matching metric/currency/unit/sample and an exact sum check. A preceding total closes the prior block. Neither co-location in a document/event nor equal amounts alone proves duplication. Independent totals remain; uncertain summary relationships mark coverage incomplete. Unknown roles are excluded. Separate unproven financial events remain disclosed duplicate candidates, never silently deduplicated by equal amount.
- Public facts and source role evidence are independently filtered. A total from a region-restricted original is not accepted as a public fallback for hidden line items. Public analysis never filters private detail out of an already-computed authorized total.

## Current snapshots and bounds

`GET /api/v1/integrations/archives/analysis` requires current `archive.read` and `archive.analyze`. `GET /api/v1/archives/analysis` requires an active current screen and produces only the public projection. `/analysis/{id}` reads a previously stored snapshot under the exact current authority and projection.

A read-only SQLite transaction rechecks authority and reads current publication references and independent manual assertions, including still-current facts from an older extraction. Search FTS/outbox rows do not supply amounts. Arithmetic runs after releasing that read snapshot. A short write transaction rechecks authority, household epoch and rebuild generation before persisting. New facts, privacy, withdrawal, reassignment or rebuild invalidate previous results. Schema stays `archive-analysis/1`; computation and snapshot validation use `archive-analysis/2`, invalidating previous algorithm snapshots. Snapshots bind algorithm version, normalized query, projection, household generation and a digest containing input observation revisions/provenance. Reads of obsolete or other-authority snapshots fail. At most 128 current snapshots are retained per household; stale ones are disposable.

Bounds: 4096 documents/facts per operation, five-second source-read budget, 256 output groups and 32 KiB serialized result. Over-bound results explicitly request a narrower query; they are never silently truncated into a complete total. Analysis does not accept a search cursor as a complete dataset.
