# Natural-language archive tools (T11)

The Brain model inventory now contains the original 13 household tools plus
seven archive tools. The MCP inventory additionally contains the host-only
`home_get_operation` recovery tool. The executable, MCP server, plugin manifest,
plugin inventory, model argument whitelist and receipt renderer must be updated
together; an old tools.json is deliberately rejected. This is development
implementation evidence, not a production deployment claim.

| Tool | Business purpose |
| --- | --- |
| home_search_archives | Literal text and structured domain/person/date/ownership search |
| home_search_archive_entities | Current family archive subjects and aliases |
| home_get_archive_evidence | Bounded current document evidence, including legacy records |
| home_get_archive_task | Original, processing and NAS status |
| home_get_archive_question | Current typed clarification, choices and version fences |
| home_answer_archive_question | User-selected typed answer against all current fences |
| home_revise_archive | Explicit value/ownership/privacy/withdrawal correction |

These tools call the actual T09/T10 authenticated integration endpoints. The
model never chooses household, credential, principal, visibility projection,
request ID, operation ID or resolution key. Brain supplies a stable SHA-256
resolution key from its own turn and trusted call reference; ordinary request
correlation is also host-generated. Clarification passes question version,
waiting task version, extraction and document revision unchanged. Core enforces
current policy, original task delegation and target versions transactionally.
Corrections require current document revision, a user reason and read+organize;
value and reassign require the current observation. Value requires an explicitly
present value, including when deliberately clearing it. Missing or stale fences
are errors, never implicit authorization to overwrite newer data.

Clarification retries of the same trusted call use the same key. Document
revisions use Core's existing compare-and-swap boundary: repeating an old
revision cannot create a second correction. An uncertain mutation result must
be queried before another intent, never automatically retried with a fresh
revision. T11 does not add an archive intake tool; native IM attachments and
message identity admission belong to T13.

The envelope remains integration schema `1` and availability `available` (or
an explicit error envelope). Archive data is independently versioned
`archive-query/1`. Search/entity pages retain coverage and cursors; lifecycle
results use a typed `result`. Required fields are checked before typed decoding
can manufacture absent scalar zero values. Unknown backend fields are dropped.
The complete MCP response, including duplicate text/structured content, is
bounded to 32 KiB. A too-large result asks for a smaller page and is not silently
truncated or treated as success. Page default is 10, maximum 25. Core performs
current authorization and evidence filtering in its T10 snapshot.

`receiptResult` validates these typed payloads before private evidence is
appended. Final `ask.mjs` output is generated by `receipt-renderer.mjs` from this
receipt, never the model's final prose. The renderer distinguishes original
context, confirmed extraction, unresolved candidates and manual corrections;
an original excerpt is not mislabeled as an unresolved extraction. Human-readable
text ranges, pages, Word paragraphs and sheet cells use compact source numbers.
A source number `R.D.E` addresses receipt R, item D and evidence E in the returned
structured receipts, which retain complete document, publication, extraction,
segment and locator IDs. No artificial medical conclusion, sum or field label is
added. Incomplete zero results explicitly do not prove absence. Typed choices
and states are shown in plain language. The existing 30-second/eight-call budget
is unchanged; budget exhaustion says the turn is incomplete.

validated synthetic health and education fixtures, indexes them, builds real

the exact same captured receipts with the final readable renderer without
another provider call.

## T12 analysis tool

`home_analyze_archives` is now part of the actual model inventory and typed receipt path. It accepts only operation/count/metric and ordinary archive filters; Core supplies authority and household timezone. Its `archive-analysis/1` payload retains decimal strings, input provenance, archived-only coverage, generation and the exact normalized query. Brain rejects receipts for a different normalized query. OpenClaw renders Core's exact amounts, denominators, ratio changes and citations rather than model arithmetic. See `internal/archive/README.analyze.md` and the T12 evidence for current synthetic Core→MCP→Brain verification; the T11 live model capture above remains historical T11 evidence, not a new T12 provider invocation.
