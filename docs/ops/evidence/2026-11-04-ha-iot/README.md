## 当前状态

2026-11-04：统一模型、只读 HA 适配器、持久化、House API 和房间设备卡片已实现。首批为加湿器、温湿度计、鱼缸，13 项能力。用户选择先用 OnePlus Android TV 客户端验收，TCL 后续单独验收。当前仍不能声明完整实机闭环完成。

候选提交 `a38fe0f` 已整合当日已上线的按需缓存版本；发布以原运行后端为基线叠加补丁，保留已有发布内容。候选签名复用既有身份。生产已升级至 schema 18，但首次后台同步未达标后自动恢复原配置，IoT 保持关闭，Core 与两个 NAS 照片来源正常。未复制照片或其他 NAS 原件。

## 已验证

- Go `make check` 通过；受影响 IoT、持久化、应用与 WebSocket 路径的 race 检查通过。
- 最终前端 88 个测试文件、661 项测试通过，lint、类型检查和构建通过。一次并发运行的农历全日期测试超时；单独复查与最终完整运行通过。
- 签名候选在独立数据库、回环 API 中经 CA 验证连接真实 HA，13/13 能力可用；API 不含提供方实体标识或端点。终止后服务已退出。
- 独立数据库副本完成 schema 17→18 演练：原有 74 张表数据摘要不变，integrity/FK 检查通过，旧版本 schema guard 拒绝打开新库。
- 合成页面验证关闭、合法零值、未知、不可用、多房间和方向键滚动；804×384 小屏布局检查通过。完整 4K 视觉验收尚未完成。
- 授权清除通知与重连边界均立即屏蔽旧 IoT；即使下一次 HTTP 读取失败也不恢复旧值。普通更新保留画面与焦点。相关回归和队列合并检查通过。

## 当前阻碍与待验证

相同签名候选在前台可连接 HA，在隔离 launchd agent 中 TCP 连接反复报 `no route to host`。系统本地网络列表未出现 Atrium；正在验证后台代码身份及本地网络权限问题，尚未将推断写为已确认根因。生产诊断性重新启用被自动审批拒绝后，未执行该路径；已请求用户批准应用身份与网络授权，以及隔离验证通过后的受保护重试。

尚待 OnePlus 真实页面、至少两类设备真实变化、10 次 HA→屏幕延迟测量、真实断线恢复和 HA/主机重启验收。单次静态读数、合成测试及前台启动成功不能替代这些结果。
