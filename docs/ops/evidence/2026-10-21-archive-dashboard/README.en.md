The frontend comes from `6bca2a1`. Other main-branch backend changes are excluded; schema remains 17.

- The supplied HTML is implemented as five cards in three columns: milk spans two columns, archive composition is on the right, and height, weight and financial amounts occupy the second row. Sidebar counts, avatars and selection, in-card day/week/month controls, gradient curves, and recent archive icons/dates/tags follow the design. Missing records keep empty cards.
- Milk follows the current filter: today uses Core totals and record counts; week/month show the mean of recorded days and the number of recorded days. Missing days are not zero-filled. Growth shows the selected person's latest measurement and change from the previous one. Units, currencies and samples remain separate; derived means requiring division and percentages round to two places; a single value retains Core precision.
- Composition and finance cover the whole household's public archives independently of the selected person, domain or page. Finance shows confirmed amounts over six calendar months, separately by currency. Since existing records cannot uniformly distinguish income from expenses, the card is labelled financial amounts. A missing current month is not zero.
- `GET /api/v1/archives/overview` requires a current screen credential and rejects filter parameters. Counts share an authorization and epoch/generation read snapshot with the current list. Confirmation requires verifiable parsing and public attribution; pending counts refer to documents. The read-only projection has two-second, 1,000-document, 1 MiB and public-entity budgets. Incomplete coverage is explicit, and unrelated alias payloads are not loaded.
- Any parallel batch failure immediately hides the old snapshot. Generation changes, revoked access and late responses have regression coverage; pending reads retain the 30-second maximum validity limit. Projected queries, evidence/original previews, detail return and pagination remain available.
- All 541 frontend tests across 77 files passed, followed by 24 related tests after the native-title width fix, together with lint, type checking, production build and Chrome 66 API checks. The full serial Go suite and overview store/HTTP race checks passed, as did four-package compatibility regressions over the narrowly patched deployed backend.

The official OnePlus app passed new-asset, five-card layout, public overview, person view, native direction-key and detail-return checks, and was left on Archives.
- The existing signing identity and designated requirement were preserved. Only Core and provenance changed among 58 manifest entries; the other 56 stayed byte-identical. An isolated new database passed real screen pairing, three synthetic legacy family records, index catch-up and embedded-resource hash checks.
- Ingress and Core were stopped for a consistent private backup. All 45 SQLite copies passed integrity and foreign-key checks. After atomic replacement, health, configuration, household archives, photo index and source identities matched the pre-deployment checks.
