# 房屋：中枢状态首版

2026-09-12。M3-B 的实现设计，沿用已经在 OnePlus 验证的纸白青瓷、宋体标题与本地黑体正文。实际家庭资料、环境传感器与日历尚未接入，不能用样例数据填充生产页面。

数据契约见 [家庭概览契约](../../tech/2026-09/atrium-home-hub/family-overview-design.md)。本页为只读信息页，不提供房屋设备控制。

## 内容与构图

主导航按“首页、照片、房屋、设置”排列，设置保留在末尾；方向只移动焦点，确认才切页。首页原有照片/状态入口保持原功能。

房屋页使用现有 Masthead、标题“房屋”和主导航。主体分两栏：左侧约三分之二展示“中枢与来源”，右侧展示“房屋资料”和“环境数据”。左侧按 Core 最近响应、此屏幕实时连接、授权照片来源的检查状态排列，不把这些状态汇总成“房屋正常”。

- Core 显示“最近可响应”及响应时间，连接是否实时在线另按 WebSocket 会话表达。
- NAS 每个来源单独显示名称、健康、最近检查与最近可读时间；有效但异常的观测照常显示。过期明确标“状态待更新”，同时保留“上次观测：离线/异常”等历史含义。
- 无来源使用“没有可展示的照片来源”；读取失败、尚未完成首次检查与成功空集合分开。
- 房屋资料未提供时显示“尚未填写”，环境数据未接入时显示“未接入”；没有伪造房间、温湿度、正常数值或不可用的编辑按钮。
- 本批不展示共享容量，不借最近健康检查时间证明旧容量新鲜。

“重新检查”与状态反馈固定在主体底部，不能随详情滚出可视区域。详情较多时只滚动内容区域。沿用 M2 字号；短视口隐藏重复 Masthead、缩减间距，不通过缩小正文解决溢出。检查 1920×1080、3840×2160、804×384，以及长来源名和多个来源。

## 遥控与返回

进入页面时聚焦“中枢与来源”详情区域；返回本页时优先恢复原导航按钮，目标缺失则回到详情区域。

| 当前区域 | 方向/确认 | 结果 |
| --- | --- | --- |
| 详情 | 上/下 | 按可视高度分段滚动；到底后向下进入重新检查 |
| 详情 | 右 | 进入重新检查 |
| 详情 | 左 | 进入主导航当前房屋项 |
| 重新检查 | 确认 | 重读公开投影，保持本按钮焦点，反馈检查结果 |
| 重新检查 | 上 | 回到详情 |
| 重新检查 | 下 | 进入主导航房屋项 |
| 主导航 | 左/右 | 移动，边缘停留；按实际导航长度处理 |
| 主导航 | 上 | 回到详情 |
| 房屋页任意区域 | 返回 | 返回来源页及原入口焦点；无来源时回首页 |

只读详情无需确认键执行动作。一次 Back 仍只消费一层，沿用 M2 网页与原生菜单协同。房屋 → 照片/设置 → 返回也必须恢复原来的房屋导航入口。数据重读、过期状态变化和远程 refresh 不抢焦点。

## 独立加载与授权

可见房屋页每 30 秒重取；进入、回前台、重连及相关 nas/home 通知触发重取，合并并发请求。用服务器校时判断 60 秒过期，不能依赖设备时钟正确。停止展示房屋页或进入后台时停止周期请求。

房屋 API 的成功不能被 `/home` 照片统计失败遮住。连接页在非 superseded 情况下提供“查看中枢状态”入口：确认后先通过 House API 做真实鉴权，成功才进入房屋。授权过期、撤销和配对优先级不变；401 回到配对，superseded 不通过这一入口绕过单会话规则。

有效授权下，已进入房屋页时 WS 断线可保留明确标旧的公开投影，不能因为照片 `/home` 失败将独立房屋页面强制替换。HTTP 暂时失败显示 stale/failed；服务端明确返回来源 failed 空条目或撤下来源时必须清除旧内容。新 family 状态接受授权代次、请求序号和同步清空保护，不持久化家庭内容。

新增本地 house 路由与状态上报，远程 navigate 继续只允许 dashboard/photos。更新涉及导航顺序的既有行为测试和实机脚本，以完整目标流程验收，不能靠直接设置 DOM 焦点跳过遥控路径。

## 交付证据

API 鉴权/故障隔离与客户端生命周期用例通过后，浏览器验证三尺寸、来源移除、过期、照片统计失败、旧响应晚到、焦点与滚动。再部署到 OnePlus 检查真实 NAS 状态显示和全遥控往返，并回归已有照片/AI 控制。此批完成仅代表房屋中枢状态首版，完整 M3 仍需真实共享日历与家庭内容。
