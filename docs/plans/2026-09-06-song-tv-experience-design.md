# Atrium TV 视觉与交互设计

版本：0.1 · 讨论稿 · 2026-09-06

2026-09-12 更新：AI 首期已完成，现进入产品视觉迭代。首轮照片版的具体构图、字体、token 与键位以 [宋式照片版规范](../design/song-tv-v1/spec.md) 和 [可操作原型](../design/song-tv-v1/prototype.html) 为准；本文保留扩展到简报、房屋、日历和视频的整体讨论。

本文承载从三端技术验证进入家庭产品迭代后的设计讨论，供产品、视觉设计和开发共同使用。它不是已实现功能清单，也不是最终视觉定稿。

历史优先级：用户曾要求先做 [AI Brain 与 home-mcp 技术方案](../tech/2026-09/atrium-home-hub/ai-brain-home-mcp-design.md)。该首期已验收，视觉工作已恢复；不因此撤销既有设计决策。

## 1. 已确认与待确认

**用户已确认：**

- 第一版验证 Mac mini、群晖 NAS、TV 三者之间的技术链路；下一阶段优先迭代产品。
- 视觉采用宋式美学。
- 照片能够选择、打开预览及切换；内容范围扩展到视频、简报、房屋信息、日历。
- 简报定义为家庭今日概览，汇总日程、家庭提示和房屋状态。
- TV 是主要公共显示终端；遥控器是主要输入方式。OnePlus 6T 继续作为 Android TV 测试终端。
- Mac 断电恢复、NAS 自动挂载暂不做。

**下文除上述事项外均为设计建议。** 首页比例、配色数值、按键细节、房屋字段、数据源和交付轮次仍可调整。本文不默认授权访问私人日历或新增 NAS 目录。

与原 PRD 的关系：保留三端架构、只读来源、鉴权和控制协议边界；视频属于原 PRD 明确排除、现由用户提出的新范围。日历由可延期方向进入本轮设计。简报和房屋信息需要新增需求定义，不能直接视为现有 Widget 已完成。

## 2. 产品体验：平时可看，拿起遥控即可使用

Atrium 在客厅呈现家庭影像与当天值得知道的信息。被动观看时画面安静、信息有限；主动使用时有清楚的入口、焦点和返回路径。

建议设置两种界面状态：

- **常驻展示**：家庭照片、日期时间、今日信息摘要与简短设备状态。不播放有声视频，不强制翻动文字。
- **主动浏览**：遥控器唤出导航，进入影像、简报、房屋或日历，查看更完整内容。

首屏不同时铺开所有详情。未接入的模块不显示虚构读数或永久空卡片，可在设置中看到“尚未连接”。系统正常状态保持简洁；异常使用文字加图形表达，详细诊断放入状态页。

主动打开的照片、视频、日历和简报不因空闲超时自动跳回首页。视频不被照片轮播打断；既有 `show` 保持单图、`refresh` 保持页面的语义继续有效。

## 3. 宋式美学的产品化表达

这里将“宋式美学”解释为本项目的设计语言：留白、节制、温润、清晰的比例与细节秩序；并非历史样式复原。

### 3.1 三种可选表达

| 方向 | 表达 | 取舍 |
| --- | --- | --- |
| **纸白与青瓷（建议默认）** | 暖纸色背景、墨色文字、青瓷色点缀、装裱般的照片留白 | 适合信息阅读及家庭气质；需控制电视大面积亮度 |
| 墨夜与月白 | 深墨背景、暖白文字、克制的青色焦点 | 适合夜间和影像；照片以外的层级要保持清楚 |
| 素绢与山色 | 灰米背景、更柔和的层次与少量纹理 | 质感柔和；小字和焦点容易对比不足，需要更严格校验 |

建议先做“纸白与青瓷”主方案和一张“墨夜”对照页。自动昼夜切换另行确定，不能据此宣称已有主题功能。

### 3.2 视觉规范起点

| 元素 | 初稿建议 |
| --- | --- |
| 背景 | 暖纸白 `#F2EEE5`；大片纯白适当收敛亮度 |
| 主文字 | 墨色 `#28332F` |
| 次级文字 | 灰墨 `#59645D`；不使用过浅灰承载关键信息 |
| 内容底色 | 素绢 `#E6DFD2`，以留白和细线组织区域 |
| 操作强调 | 深青 `#315E54`，用于焦点、选中或主要操作 |
| 轻装饰 | 淡青 `#BDD0C6`，不单独用作焦点或正文 |
| 告警 | 赭色 `#8B4A35` 配明确文字与图标；具体对比度须在设计验证 |
| 字体 | 标题可用清晰的宋体/衬线体，正文、时间和状态使用易读字体；字体文件本地随应用提供，选型及许可待核验 |
| 图形 | 简洁一致的线性图标；图标配中文名称，不靠抽象符号猜功能 |
| 材质 | 可选极轻纸纹；不覆盖照片、不影响文字，不使用大面积仿旧污渍 |
| 图片 | 保留原始色彩；不统一加泛黄、水墨或低饱和滤镜 |

以 1920×1080 构图为起点：外侧安全留白约 64–80 设计像素；核心文字约 32–40，标题约 48–64，辅助文字约 26–28。以上是设计目标，不直接等同于 WebView CSS 像素，需适配 4K 与高 DPI 测试机，并实测 2–3 米阅读。

宋体用于少量标题时也不选过细字重。不用复杂书法、竖排长文、古文按钮名、厚重仿木边框或满屏印章替代信息层级。按钮仍叫“播放”“返回”“日历”。

### 3.3 焦点与动效

- 焦点使用清楚的深青外框、间距和轻微抬升；选中状态另有标记，避免与焦点混淆。
- 初稿动效：焦点约 120–180 ms，页面过渡约 180–240 ms，照片淡入约 400–600 ms，均待低性能设备验证。
- 不用持续漂浮、粒子或强烈缩放；减少动效时可立即切换。
- 文字始终稳定，不随相片交叉淡入；切换失败保留仍可用的上一张图片并说明原因。

## 4. 信息架构与首页构图

建议一级导航：**首页 · 影像 · 简报 · 房屋 · 日历**。设置通过可见的独立入口进入，不依赖遥控器上一定有菜单键。

```text
首页
├─ 当前照片 → 照片预览 → 上一张 / 下一张
├─ 影像 → 集合与照片/视频筛选 → 照片预览 / 视频播放
├─ 简报 → 今日摘要 → 条目详情
├─ 房屋 → 房间与信息 → 信息详情
├─ 日历 → 今日/未来日程 → 日期与事件详情
└─ 设置 → 展示偏好 / 数据连接状态 / 设备状态
```

建议首页约 2/3 为主照片、1/3 为时间日期与“今日”摘要。侧栏最多呈现少量近期日程或提示，房屋异常优先出现；无数据时自然收拢。底部导航在操作时完整显示，常驻时留下简短操作提示和系统状态。

整体采用非对称但稳定的构图；照片像放在素色画幅中，信息像简洁题签。布局不追求所有模块面积相等。具体比例需通过横图、竖图和不同信息量的设计稿验证。

## 5. 照片与影像库

用户所说“点击”，在 TV 上统一理解为“焦点选中后按确认”；鼠标或触屏点击映射到同一动作，属于辅助输入。

### 5.1 首页与图库

- 首页确认当前照片进入全屏预览；进入时暂停首页轮播。
- 影像库提供家庭照片、最近新增、今天拍摄、全部影像等集合入口；“照片 / 视频 / 全部”作为内容筛选建议。
- 视频封面有播放图标和时长，照片不使用播放图标。焦点只预览封面，不自动播放视频。
- 网格按最终版式确定列数；遥控移动算法与实际列数一致，不固定假定五列。
- 确认卡片进入对应照片或视频；返回恢复集合、筛选、滚动位置和原卡片焦点。资源已移除时选择最近的有效位置并说明。

### 5.2 照片预览

- 主图默认完整显示，横竖比例保持不变。竖图两侧留素色空间；缩略图可以裁切，但预览不默认裁掉人物或边缘。
- 左右切换当前浏览序列中的上一张/下一张；预取相邻预览，失败可跳过并显示简短原因。
- 确认键显示/隐藏操作层，可查看日期或进入明确的“开始轮播”动作。手动看图与自动轮播需要可辨认状态。
- 返回：操作层打开时先关闭；预览层再返回来源页面。焦点和顺序在往返中保留。
- “首页随机照片进入预览后的相邻序列”需要新增明确的客户端序列设计；不假定现有随机 API 已支持稳定的前后张查询。
- 最近新增继续指 Atrium 首次发现；未知拍摄时间显示“拍摄时间未知”，不推断人物、地点或事件。

## 6. 视频体验（新增能力）

视频与照片同属影像库，但使用独立播放状态。第一阶段建议仅手动播放，首页只展示封面，不把有声视频混入被动照片轮播。

| 场景 | 交互建议 |
| --- | --- |
| 选择视频 | 确认进入播放器并开始播放；自动播放被平台拒绝时显示明确播放按钮 |
| 播放中确认 | 显示控制层并聚焦播放/暂停；再次确认执行按钮动作 |
| 控制层 | 播放/暂停、进度、上一段/下一段（有相邻视频时） |
| 进度操作 | 聚焦进度条后左右预览目标时间，确认提交跳转，返回取消未提交跳转 |
| 音量 | 使用系统音量键；进入播放器不主动提高音量 |
| 返回 | 控制层打开时先关闭；再返回图库并停止播放，不在后台继续出声 |
| 播放完毕 | 停留结束画面，提供重播/下一段/返回；默认不连续自动播放 |
| 缓冲或失败 | 区分加载、缓冲、格式不支持和连接失败；提供重试/返回 |

视频要求新增索引类型、时长/封面/格式元数据、受权媒体读取、进度状态与播放器。是否采用 WebView 视频或原生播放器尚未决定；用真实家庭样本验证画面、声音、拖动、横竖方向与资源占用后再选型。

暂不承诺所有 NAS 视频都可播放，也不直接纳入全量实时转码。转码、字幕、HDR、跨设备续播、混合照片视频轮播等在样本验证后另列需求。即使需要原生播放器，首页与信息页面仍可沿用当前 WebView。

离开应用暂停播放；重新进入提供恢复动作。照片控制命令与视频播放冲突的优先级、命令已应用的判定要单独补协议：不把“播放器打开”当成“视频已经成功播放”，新语义确定前不扩展既有 `show`。

## 7. 简报

**用户已确认：家庭今日概览。** 汇总日程、家庭提示和房屋状态，第一阶段采用确定性的数据汇总，不依赖 AI 或外部新闻。

建议基础形态：日期、最多数条关键信息及明确来源。首页显示短摘要，详情页按条目阅读；长内容分页，不使用远距离难读的滚动跑马灯。

- 核心内容：近期日程、家庭提示、已接入的房屋状态；天气仅在另行配置并决定展示后出现。
- 每条包含来源、更新时间及相关详情入口，区分“无事项”“未连接”“同步失败”。
- AI 摘要不在本次简报范围；以后若扩展，应另行定义生成来源、时间、失败/过期行为与事实追溯。
- 不把未知数据写成“家中一切正常”；不将没有数据的统计写成零。

## 8. 房屋信息

“房屋信息”的具体含义待确认，设计先区分三层，避免将 Core/NAS 在线等同于整个家庭状态：

| 层次 | 候选内容 | 当前边界 |
| --- | --- | --- |
| 房屋资料 | 房间名称、楼层/区域、公开家庭说明 | 需新增结构化配置；不默认展示精确住址或门锁密码 |
| 居住环境 | 温湿度、空气质量、门窗状态 | 尚无已确认数据源；需要独立设备/传感器接入 |
| 中枢状态 | Mac Core、NAS、TV 连接、照片同步 | 部分已有数据，可以先做中文易读展示 |

房屋页建议按房间分组，突出有用信息和更新时间；详情中显示来源及过期状态。无传感器时不画假平面图热区、不填模拟温度。

本轮先讨论只读展示。灯光、空调、门锁等控制不因增加房屋页而自动纳入；若需要控制，另行定义设备能力与权限。

## 9. 日历

首页显示下一件事及今日少量日程；日历页建议默认“今日与未来七天”议程，月历作为次级入口，更便于远距离阅读。

- 方向键选择日期/事件，确认打开详情，返回恢复原日期与焦点。
- 全天事项与定时事项分开；遵循家庭时区，明确跨日和重复事件。
- 首期只读，不在 TV 上输入长文本或创建复杂日程。
- 数据源待定，可评估维护者配置的家庭日历或授权同步；连接配置由维护端处理，TV 不承担完整账号登录流程。
- 仅展示明确允许在公共屏出现的字段；私人会议描述、地址、参会人不默认公开。
- “今天没有安排”只用于成功同步且无事件；未连接、离线和过期有不同文案。

## 10. 遥控器的一致规则

| 场景 | 规则建议 |
| --- | --- |
| 首页初始焦点 | 当前照片；首个方向键显示导航与焦点并按方向移动 |
| 常驻首页确认 | 直接预览当前照片，不用先点击一次唤醒再点一次打开 |
| 一级导航 | 左右选入口、确认进入；焦点停留不触发页面切换或网络操作 |
| 区域与网格 | 上下跨相邻区域，左右沿行移动；边缘默认停住，不突然环绕 |
| 详情与弹层 | 先关闭最上层，再返回来源；不穿透到背景页面 |
| 首页返回 | 若在导航先回主照片；主照片处显示含“继续使用/退出”的小菜单，Home 键始终交给系统 |
| 快速连续按键 | 及时更新焦点，不积压动画；进入/返回只处理一次有效动作 |
| 状态变化 | 新数据不抢焦点、不自动打开弹层；当前资源失效时安全退出并解释 |

现有 Android 双击返回/菜单键行为需在实施时与上述规则统一；视频控制、网页弹层与原生退出菜单不能同时处理同一个返回事件。

## 11. 公共屏幕与异常状态

配对、加载、空数据、离线、部分错误与无权限应与主界面共用字体、色彩和焦点规范。连接页简明说明连接对象与下一步，证书失败不提供跳过验证入口。

照片/视频仅来自授权范围；新增视频来源不会自动扩大扫描目录。日历、简报、房屋模块分别声明公开字段。现有照片离线授权期限仍生效，不能为长时间静态展示而跳过；视频与其他新内容需定义对应缓存及撤销行为。

NAS 离线时保留仍被授权且可用的照片；视频缺少可用数据时显示暂不可播放。仅一个模块失败时其他模块继续显示。

设计原型中的示例内容必须标注为示例，不连接真实家庭数据；真实联调时使用授权内容，不把家庭照片、住址或私密日程写入仓库。

## 12. 设计交付与实施顺序

| 阶段 | 交付物 | 进入下一阶段的依据 |
| --- | --- | --- |
| A · 明确设计 | 本文、首页两种明暗方向、字体/配色/间距/焦点规范 | 用户确认首页风格和信息主次；简报/房屋定义明确 |
| B · 完整原型 | 首页、影像库、照片、视频播放器、简报、房屋、日历、设置及关键异常状态 | 方向/确认/返回可完整走通；照片横竖图、长标题、空数据都有设计 |
| C · 先落地照片与导航 | 新 TV 页面、集合切换、图片预览/切换、焦点与返回位置恢复 | OnePlus 实测；保持控制协议和断线行为 |
| D · 视频与信息功能 | 经样本验证的视频链路；有实际数据源的简报/房屋/日历 | 按模块验收，不用占位界面宣称接入完成 |
| E · 展示与稳定性验收 | 1080p/4K 检查、真实电视/遥控器、性能、长稳及发布包 | 与原 PRD 的发布门槛合并记录；暂停的运维项仍明确列出 |

B 阶段可以用明确标注的样例内容验证完整体验；C/D 才接入真实能力。本文不承诺这些新增模块已经实现。

验收需要至少覆盖：2–3 米可读；焦点清楚且不被边缘裁切；全流程无需触屏；照片切换失败可恢复；视频播放/暂停/跳转/退出无后台残留声音；数据缺失不伪造正常；用户浏览不被自动轮播或后台通知打断。
