# 视频播放器实现基线

2026-09-14，承接产品开发计划 M4。本文记录根据真实样本选定的实现方向，不表示视频功能或正式电视验收已完成。

## 方案选择

先使用现有 Android WebView 与 HTML video。授权 NAS 根内已取得 MP4/MOV、H.264/HEVC、AAC、横竖屏和旋转样本；OnePlus 原型已证明解码路径可用。遥控由原生 evaluateJavascript 分发，合成事件没有 Chromium 用户激活，因此容器显式允许不带浏览器手势的媒体播放。页面承担仅在明确确认后播放的产品规则。

原生播放器保留为实际目标电视无法满足兼容性或生命周期要求时的备选，会增加桥接、授权传递和状态同步成本；全量实时转码本轮不做。OnePlus 上通过的 HEVC 样本不能推导所有电视均支持 HEVC。播放失败显示当前设备不支持或读取失败，不伪装空列表。

## 数据与访问

- 图片、视频继续使用 `/Volumes/home/Photos` 同一授权根，按媒体类型区分，不要求新目录。
- 视频使用独立索引与迁移，保留现有照片身份、查询与任务语义；只读探测元数据并生成受预算约束的本地封面。
- 先支持实测 MP4/MOV 容器；保存编码、时长、显示尺寸、旋转及可播放状态。不按后缀保证可播放，不把视频交给图片解码器。
- Core 提供同源、按屏幕授权的视频列表、封面和内容接口。客户端只接收媒体 ID，不接收 NAS 绝对路径。
- 内容接口需要鉴权、授权撤销、来源身份核对、路径与符号链接限制、GET/HEAD、单 Range/416、长度与内容类型测试。请求取消要释放读取资源；NAS 降级返回明确错误。
- 原型的 CDP 请求拦截只用于兼容性实验，不进入生产，也不能代替真实 HTTP Range 与权限验收。

## 宋式界面与遥控

视频列表延续纸白、青瓷焦点、留白与宋体标题，封面附时长。导航打开列表，确认封面进入预览待播态；再次确认明确播放，页面进入与恢复不自动播放。保留返回来源卡片及滚动位置。

播放器使用墨色背景、完整比例画面，竖屏保留两侧留白。确认切换播放/暂停，左右以固定步长跳转，上下显示操作栏并移动焦点；操作栏提供播放/暂停、进度、返回。返回先退出播放页并释放媒体，不继续后台声音；加载、缓冲、结束、读取失败和格式不支持均有可遥控操作。

隐藏、切后台、路由离开和授权失效均需暂停；离开时清除 src 并 load 释放资源。异步 play 完成时再次核对播放意图与可见性，防止加载期间切后台后迟到续播。前台恢复保持暂停。WebView.onPause 不能替代页面生命周期控制。

## 实施顺序与出口

1. 容器遥控播放修复及真实样本复测：记录修复前 NotAllowedError、修复后普通遥控播放、设备画面、音频解码、跳转、后台暂停与返回。声音听感另列待验收。
2. 独立视频迁移/索引/元数据/封面，针对同目录混合媒体、不支持文件、改名删除、NAS 超时和取消写有意义的回归。
3. 列表/封面/内容契约与权限、Range 测试，先完成 Core 再接页面；限制并发与缓存预算。
4. 宋式列表和播放器、路由与状态报告、焦点恢复及上述生命周期竞态测试。
5. 从真实 Core 接口在 OnePlus 复验，同时回归照片、简报、房屋、普通月历及已有 AI 命令。旧 show 保持照片语义；新增视频命令另定契约。
6. 正式电视的画面、声音、遥控和稳定性验收；缺少目标设备或人工听感证据时明确保留门槛。

Mac 断电恢复和 NAS 自动挂载继续暂停。此方案不增加外部媒体目录、NAS 写入、自动播放或 AI 自动播放权限。
